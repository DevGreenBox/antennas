# Каталог антенн и радиооборудования — макет витрины

Работающий макет интернет-витрины технического каталога: каталог из Excel заказчика с подбором
по параметрам, поиск, карточки товаров, избранное, корзина, заявка и демонстрация процесса
«Заявка → Согласование → Оплата» в личном кабинете.

**Что это и чего здесь нет.** Это витрина. Админка, приём заказов, оплата, доставка и
уведомления будут на платформе **Admik** — витрина подключится к ней на следующем этапе
(см. «Сращивание с Admik»). Сейчас процесс заказа проигрывается демо-данными в браузере
(`localStorage`): ничего никуда не отправляется, каждое демо-действие подписано на странице.

## Быстрый старт

```bash
nvm use            # Node 24 (.nvmrc); нужен Node ≥ 22.18
npm install
npm run dev        # http://localhost:3000
```

Production-сборка: `npm run build && npm start`.

## Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` / `build` / `start` | Next.js 16 (Turbopack) |
| `npm run typecheck` / `lint` / `format:check` | TypeScript strict, ESLint, Prettier |
| `npm run import:catalog` | Пересобирает каталог из `source/Catalog_v11_for_Claude.md` в `src/data/*.generated.json` и `docs/IMPORT-REPORT.md`. Идемпотентен |
| `npm run logo` / `logo:verify` | Генерирует знак, фавиконки и схемы из параметров; проверяет, что все дуги концентричны |

| `npm run test:e2e` | Playwright, desktop 1440×900 и mobile Pixel 7 (`e2e/*.spec.ts`) |

## Данные каталога

- Источник — выгрузка `список v11.xlsx` с адресами ячеек: `source/Catalog_v11_for_Claude.md`.
- Правила разбора — `docs/DATA-RULES.md`; результат и все спорные места — `docs/IMPORT-REPORT.md`
  и служебная страница `/import-report`.
- 132 товарные строки (лист 1 — 113, лист 2 — 19) → **118 товаров**. Временная витрина =
  лист 1 + уникальные позиции листа 2; 10 строк листа 2, расходящихся с листом 1, сохранены для
  сверки и публично не показываются.
- Сгенерированный JSON руками не правится. Ручной слой — `src/data/overrides.json`
  (скрыть товар, переименовать, добавить фото, подтвердить рекомендацию); импорт его не трогает.
- Цены в копейках, валюта RUB — предположение до подтверждения заказчиком.

## Устройство

```
src/app/            маршруты App Router (22 страницы + 404)
src/components/     ui/ (примитивы), layout/ (шапка, подвал), product/, catalog/, cart/,
                    checkout/, account/, auth/, home/, content/, service/, brand/
src/lib/repository.ts   единственная точка чтения каталога (сервер)
src/lib/catalog/    движок: фильтры по категориям, частотный подбор, поиск, сортировка, URL
src/lib/store/      корзина, избранное, сессия, демо-заказы (zustand + localStorage)
src/lib/demo-*.ts   логика демо-заказов и расчётов (чистые функции, покрыты тестами)
src/types/          контракты данных каталога и заказа
docs/               INTERVIEW, DATA-RULES, IMPORT-REPORT, DESIGN, FRONTEND-API, LOGO
```

Документы: `docs/DESIGN.md` — живой дизайн-документ (карта страниц, сценарии, UI-система);
`docs/FRONTEND-API.md` — API фундамента; `PROJECT-STATE.md` — журнал решений и чекпоинты.

## Переменные окружения

См. `.env.example`. Для макета обязательна только `NEXT_PUBLIC_SITE_URL` на боевом домене
(канонические адреса, sitemap, превью ссылок); на Vercel без неё берётся адрес деплоя.

## Тесты

Юнит-тесты не требуют браузера. Для e2e нужен Chromium Playwright:

```bash
sudo npx playwright install-deps chromium   # системные библиотеки (в этой среде могут пропадать)
npx playwright install chromium
npm run build
npm run test:e2e                            # поднимет next start на :3100
E2E_BASE_URL=https://<превью>.vercel.app npm run test:e2e   # прогон по развёрнутому адресу
```

Результаты последнего прогона — `docs/TEST-REPORT.md`.

## Деплой на Vercel

Проект определяется как Next.js без настроек. Сгенерированные данные (`src/data/*.generated.json`)
и ассеты логотипа лежат в репозитории — на сборке Vercel скрипты импорта и логотипа не нужны.
Весь макет закрыт от индексации (`site.seo.allowIndexing = false`, `robots.txt: Disallow: /`).

## Сращивание с Admik

- Каталог: заменить реализацию `src/lib/repository.ts` на Storefront API Admik (сигнатуры
  функций сохранить). Типизированные характеристики (`ProductAttribute`: значение, единица,
  статус, происхождение) переносятся в EAV-атрибуты Admik; контракт slug категорий и кодов
  характеристик — `docs/DATA-RULES.md` §3–§4.
- Заказы: заменить `src/lib/store/orders.ts` + `src/lib/demo-orders.ts` на вызовы API заказов
  Admik. Модель статусов и переходов (`src/lib/order-status.ts`, `docs/DESIGN.md` §3) — это
  требования к процессу согласования, который должен поддержать Admik: заявка без оплаты →
  согласование менеджером → выставление к оплате → оплата только после подтверждения провайдера.
- Вход по коду на email, уведомления в Telegram и на почту, оплата, доставка — на стороне Admik.

## Что ждёт данных заказчика

Назначение листов 1 и 2 Excel; валюта; единица «6000–8000 ГГц»; КУ в дБ на листе 2; разъём Тип8
«N/sma-мама»; область примечания E57; повторы E49–E52 (фактически дублируют E44, E46, E47, E48);
смысл пометок «на управу» и «под рупор !»; кабель «RG-316 / RG-142»; название бренда; фотографии;
юридические реквизиты и тексты; провайдер оплаты, перевозчик. Полный список — `docs/INTERVIEW.md`
и `docs/DESIGN.md` §10.
