# Каталог антенн — макет витрины

**Объём сейчас — только макет витрины** (решение владельца, интервью 2026-10-05). Дальше витрину
подключат к платформе **Admik** (админка, заказы, оплата, доставка живут там), выкладка — **Vercel**.
Свою БД, админку, платёжные и почтовые адаптеры НЕ делаем. Бизнес-процесс
«заявка → согласование → оплата» показывается демо-данными в браузере (localStorage) и явно
подписан как демонстрация.

Источники (читать перед работой):
- `antennas.md` — ТЗ заказчика (раздел 4 — правила данных, 6 — фильтры, 9 — логотип);
- `claude.md` — протокол дизайн-координатора (этапы, документация, чекпоинты);
- `source/Catalog_v11_for_Claude.md` — выгрузка `список v11.xlsx` (адреса ячеек сохранены);
- `source/logo-original.pdf` → `source/derived/logo-original-4600.png` — исходный знак;
- `docs/INTERVIEW.md`, `docs/DATA-RULES.md`, `docs/DESIGN.md`, `PROJECT-STATE.md`.

Жёсткие правила:
- Не выдумывать товары, фото, наличие, производителя, артикулы, отзывы, преимущества, реквизиты.
- «По запросу» — отдельный тип цены, не 0. дБ и дБи — разные поля. «6000–8000 ГГц» не исправлять.
- Номер «220» — не название бренда; название бренда не подтверждено.
- Данные каталога генерирует `npm run import:catalog` из `source/` — руками JSON не править,
  ручные правки только в `src/data/overrides.json`.
- Слой доступа к данным — `src/lib/repository.ts` (потом подменяется на Admik), компоненты не
  импортируют JSON каталога напрямую.
- Интерфейс на русском. Стек: Next 16 App Router, React 19, TypeScript strict, Tailwind v4, zustand.
- Проверки перед сдачей: `npm run typecheck && npm run lint && npm run build`, e2e — Playwright.
