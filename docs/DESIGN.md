## R. Редизайн 2026-10-08 — визуальная система v2

Направление: **профессиональный B2B-каталог радиооборудования** — точность, инженерность,
системность. Основа языка — сетка, типографика, пропорции, технические данные; не декор. Бизнес-
логика, данные, маршруты, сценарии и правила честности данных (§0, §2–§4) не менялись. При
расхождении с §5 и описаниями раскладок в §2 действует этот раздел.

### R.1 Запреты (проверка «AI-шаблона»)

Нет: радиусов 20–32 px, карточек в карточках, стекла и размытия, декоративных градиентов, свечения,
bento ради bento, hero на экран, заголовков 70–100 px, pill-кнопок, иконок у каждого заголовка и
иконок в цветных квадратах, теней у карточек, выдуманных цифр, отзывов и преимуществ, слоганов,
композиции «hero → преимущества → цифры → CTA». Элемент, который не помогает понять, выбрать или
купить, не добавляется.

### R.2 Цвет (`globals.css`, единственное место HEX)

| `ink` / `ink-secondary` / `ink-muted` | #161616 / #5C5C57 / #6B6B66 | текст; на `page` 16,9 / 6,3 / 5,0 : 1 |
| `line-subtle` / `line` / `line-emphasis` / `line-strong` | #E5E5E0 / #DFDFDA / #C7C7C0 / #85857E | разделители строк / рамки / рамки кнопок и наведение / рамки полей (≥ 3:1) |
| `brand` | #FA9506 | единственный акцент: заливка главной кнопки, счётчики шапки, шкала частот. Только заливкой, текст на нём — `ink` |

Акцента — 10–20 % площади. Выбранное состояние (подкатегория, вид, чекбокс, текущий шаг) — `ink`.
Статусы: красный — только настоящая ошибка; «требует подтверждения» — нейтральная подложка
`surface-muted` и охристый знак (`Notice tone="warning"`). Демо — без своего цвета: пунктирная
рамка `demo-line` и слово «Демо».

### R.4 Сетка и отступы

Контент до 84rem (1344 px); поля 16 (< md) → 24 (md) → 40 (lg) → 48 (xl). Шаг отступов —
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96. Именованные колонки: каталог `catalog` 260 px / `catalog-wide`
288 px | выдача; товар `product` 55 : 45; корзина/заявка `golden-reverse`. Радиусы: 2 (чекбокс),
4 (кнопки, поля, чипы), 6 (карточки, панели), 10 (модальные окна, выпадающие слои). Тени — только
у всплывающих слоёв (`shadow-popover`, `shadow-overlay`, `shadow-sticky` липкой панели покупки).
Движение 120–200 ms: только opacity, фон, цвет, сдвиг на 2–4 px.

### R.5 Каркас

- **Демо-полоса** — одна строка ~34 px над шапкой, `surface-muted`, метка «Демо» в пунктирной
  рамке; < md — короткий текст + «Подробнее». Других общих демо-сообщений на странице нет; демо-
  пометки остаются только у демо-действий (панель менеджера, оплата, черновые рекомендации).
- **Шапка** — одна строка 72 px, белая, тонкая нижняя граница, липкая с lg: логотип · «Каталог»
  (раскрывает панель: категории с подкатегориями колонками, листовые — списком, внизу «Весь
  каталог» и служебные ссылки; Esc / щелчок вне / переход закрывают) · поиск 44 px
  («Модель, частота, разъём или код») · Избранное и Корзина (значок + счётчик) · Войти. < lg:
  меню · логотип · действия, поиск — строкой ниже, не липкая.
- **Подвал** — белый: знак + «Вопросы… в Telegram» + кнопка Telegram; колонки Каталог /
  Покупателям (Доставка и оплата, Контакты, Личный кабинет) / Документы; нижняя строка — валюта,
  реквизиты, «Служебное» (по флагу).

### R.6 Главная

Вступление (не hero): eyebrow «Радиочастотное оборудование» → h1 «Антенны и радиооборудование» →
подзаголовок → поиск 56 px + «Найти» → быстрые запросы (`site.catalog.quickLinks`, только
находящие позиции). Справа (≥ md) — **карта диапазонов**: по строке на категорию с частотами, каждая
позиция — полупрозрачная полоса на той же логарифмической оси, что BandScale; строка — ссылка на
категорию. Затем: «Каталог» — указатель категорий сеткой с разделителями 1 px (группы с
подкатегориями и количествами; листовые — ячейка-ссылка «Смотреть →»); «Позиции из каталога» — 4
карточки (первая позиция каждой из 4 самых больших категорий; это срез, не «популярное»); «Как
проходит покупка» — одна полоса из трёх шагов 01–03 со стрелками; спокойный блок «Не уверены в
совместимости оборудования?» с кнопкой Telegram.

### R.7 Каталог, списки, карточки

- Страница категории: крошки → h1 → подкатегории чипами → [панель подбора 260/288 px | выдача].
  Панель — не карточка: заголовок `eyebrow`, группы с тонкими разделителями. Выдача: «Найдено: N»
  · сортировка · «Список / Плитка»; выбранные параметры чипами над результатами, «Сбросить всё».
  < lg — липкая панель «Параметры · Сортировка», подбор — Drawer.
- **Список (вид по умолчанию)** — `ProductList` / `ProductListItem` везде (каталог, поиск,
  избранное): миниатюра 80 px (64 на узком) · название-ссылка, код Mono · характеристики «подпись
  над значением» (колонки категории `columnsForCategory`, в смешанном варианте — `getSpecLine`) с
  мини-шкалой частоты · справа цена 22 px, закладка и «В корзину». Раскладка — по ширине списка
  (container queries): < 36rem — карточка; ≥ 52rem — характеристики в одну линию. Таблицы больше нет.
- **Плитка** — `ProductCard`: медиа 4:3 (фото или заглушка `NoPhoto`) → категория → название →
  код → ключевые параметры → цена → «В корзину» + закладка. Рамка 1 px, радиус 6, без тени.
- **Медиа** — `ProductMedia`: фото `object-contain` или нейтральная заглушка со схемным знаком
  категории (линия 1,5 px на любом размере). Выдуманных изображений нет.
- **Подбор и навигация** (уточняет §5.9.17–5.9.23, §5.9.37): подкатегории — белые чипы с рамкой
  `line`, выбранная — заливка `ink`; в шапке панели — «Сбросить» (как в Drawer), «Сбросить всё» —
  в строке выбранных параметров; группа частоты — «Частота, МГц». Чипы выбранных параметров:
  параметр `ink-secondary`, значение `ink`, рамка `line-emphasis`. Пагинация: «Назад/Вперёд» —
  текст со стрелкой, номера без рамок, текущий — `ink`. Пустые состояния — текст на верхней линии.
  На < lg все цели — 44 px (чипы, пагинация, крошки, панель «Параметры · Сортировка», вид, футер
  Drawer).
- **Поиск** (§2.7): под h1 — «По запросу «q»» (скрыто, когда ничего не найдено — запрос уже в
  заголовке пустого состояния); «Страницы сайта» и «Категории каталога» — разделы с `eyebrow`.

### R.8 Товар

Первый экран 55 : 45. Слева медиа 4:3, липкое (≥ lg; < lg без фото — не показывается). Справа:
листовая категория (`eyebrow`, ссылка) → h1 30–34 px → «Код ANT-001 · Внутренний код магазина…» →
пометка «Требуется подтверждение характеристик» (если есть расхождение листов; нейтральная) →
частота крупно со шкалой и делениями → остальные ключевые параметры сеткой → цена 30 px и подпись →
количество + «В корзину» (primary) + закладка, 48 px → «Доставку рассчитывает менеджер…».
< lg: когда ряд покупки ушёл вверх, снизу появляется липкая панель «цена · В корзину».
Ниже — «Характеристики» (заголовок в левой колонке; пары «подпись — значение» с разделителем
`line-subtle`), «Пометки из прайса», затем закрытый `<details>` **«Техническая информация об
источнике данных»**: происхождение значений (ячейка, исходный текст, фрагменты) и строки прайса.
Данные и правила прежние — изменилась только подача: покупатель сначала видит товар. Затем «К
этому товару подойдёт» — сетка карточек 2/3/4 колонки (одна карточка не растягивается).

### R.9 Контентные и служебные страницы, мобильное меню

- «Доставка и оплата», «Контакты» (уточняет §2.17–2.18): полоса шагов процесса во всю ширину, затем
  разделы строками — заголовок в левой колонке шириной колонки подбора, текст справа до `measure`
  (65ch); разделители `line` / `line-subtle`. Карточек и иконок в кругах нет. «Реквизиты будут
  добавлены» — нейтральный блок с линией 2 px слева (пунктир занят под демо).
- Документы (§2.19): с lg оглавление — липкая левая колонка (`eyebrow`, номера Mono), документ
  справа до 65ch; пометка «Документ готовится» сразу под h1.
- 404 (§2.22): `eyebrow` «Ошибка 404», h1, пояснение, компактный поиск, «Каталог» и «Главная»
  строками со стрелкой. global-error — строка со знаком и ссылкой на главную (шапки там нет).
- Служебные `/import-report`, `/brand` (§2.20–2.21): разделы `ServiceSection` (линия сверху, h2,
  описание), таблицы `SERVICE_TABLE` (без внешней рамки, шапка на `surface-subtle`, разделители
  `line-subtle`); сводка импорта и образцы знака — одна рамка с внутренними линиями 1 px вместо
  отдельных ячеек; цифры и логика без изменений.
- Мобильное меню (§5.9.1): те же разделы; заголовки групп — `eyebrow`, строки ≥ 44 px с тонкими
  разделителями, подкатегории — на вертикальной линии дерева, количества Mono; текущая страница —
  `ink`, полужирный, подчёркнут.

### R.10 Покупка и личный кабинет

Уточняет §2.9–2.16 и §5.9.29.
- **Корзина**: один список с тонкими разделителями вместо таблицы и отдельных мобильных карточек.
  Строка: миниатюра `ProductMedia thumb`, название и код, цена за штуку, количество, сумма,
  удаление. Раскладка — по ширине списка (широкая с 40rem). С lg две колонки, сводка липкая.
  Промокод (демо) — под «Оформить заявку», одной строкой с бейджем «Демо».
- **Сводка заказа**: белая панель, рамка `line`, радиус 6; подпись под итогом — отдельной строкой.
- **Заявка**: форма — белая панель, разделы через тонкие линии; демо-пометка — одна строка у
  «Отправить заявку». Сводка липкая с lg.
- **Заявка отправлена**: номер со статусом → «Открыть заказ» → демо-пометка → «Что дальше» с
  шагами процесса (`ProcessSteps current={2}`).
- **Вход**: белая панель в колонке `form`; демо-код — строка внутри формы.
- **Кабинет**: общая демо-пометка — одна строка под содержимым («Сбросить демо-данные»), без
  плашки сверху. Заказ: позиции → сводка и лента статусов (не липкие: вместе выше экрана) →
  версии расчёта, покупатель, документы, панель менеджера (демо); в шапке — ссылка «Демо · К
  действиям менеджера». Цвет плашки статуса: нейтральный по ходу заказа, оранжевый «Ожидает
  оплаты», зелёный «Оплачен», отмена — нейтральная. Лента не повторяет описание текущего статуса.
- **Оплата**: сумма и «Оплатить» — одна белая панель, «Демо · деньги не списываются» — только до
  оплаты; панель ответа провайдера (демо) — рядом, не внутри.
- Пустые состояния сразу под заголовком страницы — `EmptyState compact`. Переключатель «Частное
  лицо / Организация» и кнопки диалогов — 44 px на < lg.

### R.11 Проверка перед сдачей

Каждая страница на 1440 / 1280 / 1024 / 768 / 390: нет горизонтальной прокрутки, цели нажатия ≥ 44
на < lg, видимый фокус, нет лишних карточек и иконок, нет повторяющихся демо-сообщений.

## 0. Принципы

Эти правила решают спорные случаи, которые документ не предусмотрел.

1. **Сначала товар и его данные.** Это инструмент технического подбора. Элемент, который не несёт
   информации о товаре, процессе или состоянии, не добавляется.
2. **Данные — честно.** У значения есть статус (подтверждено / принято по контексту / уточняется) и
   происхождение (ячейка прайса). Неизвестное — «—» с пояснением «не указано», а не «нет» и не 0.
   «По запросу» — тип цены, а не 0 ₽. Не показываем наличие, производителя, фото, отзывы,
   преимущества, реквизиты, которых нет в данных.
3. **Оранжевый — заливка, не текст.** `#FA9506` (2,24:1 на белом): фон главной кнопки, счётчики,
   знак, спектральная шкала, маркер текущего шага. Никогда — цвет текста, рамка-единственный
   признак, кольцо фокуса.
4. **Демо подписано.** Всё, что в рабочей версии делает Admik (приём заявки, вход по коду, письма,
   действия менеджера, оплата), в макете работает в браузере и помечено фиолетовым «Демо». Фиолетовый
   тон больше нигде не используется.
5. **URL — источник истины** для поиска, подбора, сортировки, вида и страницы списка.
6. **Одинаковость.** Компоненты — только из §5.9, значения — только токены §5, тексты — из §6.
   Нужен новый вариант — сначала документ.
7. **Сигнатура одна — спектральная шкала** (BandScale, §5.10): логарифмическая полоса частот у
   каждой позиции с подтверждённым диапазоном. Это главный параметр подбора, показанный графически.
   Всё остальное — сдержанное: белый фон, графитовый текст, линии 1 px, маленькие радиусы.

## 1. UX-структура

### 1.1 Кто пользуется и зачем

### 1.4 Состав магазина (claude.md §6): что есть и чего нет

| Блок | Решение |
|---|---|

| Checkout | Есть как **заявка** без оплаты (бизнес-процесс ТЗ §3) |
| Личный кабинет | Есть: заказы, уведомления, оплата — демо |
| Отзывы, рейтинги | **Нет** — данных нет, выдумывать нельзя |
| Сравнение товаров | **Нет** — заменено табличным видом списка (колонки по категории) |

| Админка | **Нет** — Admik; в макете — демо-панель менеджера |

### 2.4 Категория `/catalog/[category]`

Как §2.3, отличия:

- Неизвестный `slug` или slug подкатегории на этом уровне → `notFound()`.
- `h1` = `Category.name`, **без счётчика под ним** (как §2.3: число — у выдачи, всего в
  категории — в чипе «Все · {N}»); описание `Category.description`, если не пустое (`text-body
  text-ink-secondary max-w-text mt-3`).
- Вместо CategoryNav — **SubcategoryNav** (тот же компонент): первый чип «Все · {N}» (текущий,
  `aria-current="page"`), затем подкатегории с количествами. Показывается только у категорий с
  подкатегориями.
- Группы подбора — по категории (§4.2); колонки таблицы — по категории (§4.7).
- **Если ни одна группа подбора не проходит правило видимости** (мачты, аттенюаторы — по одной
  позиции) — FilterPanel и кнопка «Параметры» не рендерятся, список на всю ширину
  (`grid-cols-1`). Если в контексте без подбора ≤ 1 позиции — SortSelect и Pagination не
  рендерятся; без панели и сортировки нет и мобильной липкой панели.

**SEO:** title `{Category.name}`; description «{Category.name}: {N} {позиция|позиции|позиций}.
Характеристики и цены из прайса.»; canonical без параметров; BreadcrumbList.

### 2.5 Подкатегория `/catalog/[category]/[sub]`

Как §2.4, отличия: проверка `sub.parentId === category.id`, иначе `notFound()`. `h1` =
`sub.name`. SubcategoryNav показывает «Все · {N родителя}» и соседей; текущий чип — эта
подкатегория. title `{sub.name} — {parent.name}`.

### 2.12 Вход `/login`

Ширина `max-w-narrow`. Параметры: `email` (предзаполнение), `next` (куда вернуть) — через
**`safeNextPath(next, '/account')`** (`src/lib/demo-session.ts`): принимается только адрес этого же
сайта, иначе `/account`. Проверки строки «начинается с `/`, не с `//`» мало: «/\t/evil.test/»
парсер URL превращает в «//evil.test/» (табуляцию и переводы строки он выбрасывает), «/\\evil.test»
браузер читает так же. Поэтому управляющие символы и `\` запрещены сразу, путь разбирается
`new URL(next, origin)`, принимается тот же origin и путь с одним ведущим `/` (и после
нормализации), возвращается `pathname + search + hash`.

Если сессия уже есть — сразу `router.replace(next)`. Исключение: `?email=` указывает **другой**
email, чем у сессии (ссылка «Открыть заказ» из чужой заявки) — перехода нет, вместо формы текст
«Сейчас вы вошли как {current}. Ссылка ведёт в кабинет {target} — чтобы открыть её, войдите под этим
адресом.» и кнопки `primary lg` «Выйти и войти как {target}» (выход + сразу шаг 2 для нужного
адреса) / `secondary lg` «Остаться в своём кабинете» → `/account`.

**Шаг 1 — email:** `h1` «Вход в личный кабинет»; текст «Пароль не нужен: пришлём одноразовый код на
email.»; Field «Email» `lg`; Button `primary lg w-full` «Получить код»; `text-small
text-ink-secondary`: «Нет доступа к почте? Напишите в Telegram {handle}.»

**Шаг 2 — код:** тот же `h1`; «Код отправлен на {email}.» + Button `link` «Изменить email» (только
возвращает к шагу 1: действующий код не сбрасывается — тот же email снова получает тот же код с
оставшимися попытками, иначе смена шага обходила бы отсчёт и лимит попыток);
**DemoNotice** `inline`: «Демо: письмо не отправляется. Код для входа:» + код `font-mono text-title
tracking-widest` группами по 3 («481 526»); Field «Код из письма» (`inputMode="numeric"`,

## 3. Сценарий «Заявка → Согласование → Оплата»

В рабочей версии всё ниже живёт в Admik и на сервере. В макете — в браузере (localStorage) в одном
модуле **`src/lib/demo-orders.ts`** (переходы, версии, оплата) и **`src/lib/demo-pricing.ts`**
(чистые функции расчёта). Компоненты ничего не считают сами и не меняют статус напрямую — только
через функции этих модулей. Так демо повторяет правило ТЗ «суммы считаются на сервере».

### 3.1 Статусы заказа

| Код | Название | Описание для покупателя | Badge (§5.9.13) |
|---|---|---|---|
| `received` | Заявка получена | Менеджер получил заявку и свяжется с вами для согласования. | neutral |
| `negotiation` | Согласование | Менеджер уточняет состав, цены и доставку. Оплата станет доступна после согласования. | info |
| `awaiting-payment` | Ожидает оплаты | Заказ согласован. Проверьте состав и сумму и оплатите заказ. | brand |
| `paid` | Оплачен | Оплата подтверждена. Скоро заказ передадут в обработку. | success |
| `processing` | В обработке | Заказ комплектуют и готовят к отправке. | info |
| `shipped` | Отправлен | Заказ передан в доставку. | info |
| `completed` | Завершён | Заказ выполнен. | neutral |
| `cancelled` | Отменён | Заказ отменён. {Причина.} | neutral (§ R.2: отмена — состояние, не ошибка) |

Порядок «счастливого пути» (для таймлайна): `received → negotiation → awaiting-payment → paid →
processing → shipped → completed`.

### 3.2 Допустимые переходы

Любой переход, которого нет в таблице, запрещён: кнопка не рендерится, а функция
`transition()` в dev пишет `console.warn` и ничего не меняет.

| Из | В | Действие | Условия | Побочные эффекты |
|---|---|---|---|---|
| — | `received` | Покупатель: «Отправить заявку» | корзина не пуста, нет недоступных позиций, форма валидна, ключ идемпотентности новый | снимок позиций (§3.3), предварительный расчёт, событие `created`; уведомления: покупателю (email) и менеджеру (Telegram) — в демо помечены «не отправлено» |
| `received` | `negotiation` | Демо-панель: «Взять в работу» | — | событие `status` |
| `received` | `cancelled` | Демо-панель: «Отменить заказ» | выбрана причина | событие `cancelled`, уведомление |
| `negotiation` | `awaiting-payment` | Демо-панель: «Выставить к оплате» | ≥ 1 позиция; у каждой цена > 0 и кол-во 1–999; доставка указана (≥ 0); скидка ≤ сумме товаров; итог > 0 | новая версия согласования `issued` + ссылка оплаты; событие `quote-issued`; уведомление «ожидает оплаты» |
| `negotiation` | `cancelled` | Демо-панель: «Отменить заказ» | выбрана причина | как выше |
| `awaiting-payment` | `paid` | Страница оплаты: «Провайдер подтвердил оплату» | есть попытка `pending` по **действующей** версии; сумма попытки = итог версии; заказ ещё не оплачен | попытка `confirmed`, версия `paid`, событие `payment-confirmed`, уведомления покупателю и менеджеру; **повтор — без изменений** (§3.7) |
| `awaiting-payment` | `negotiation` | Демо-панель: «Изменить сумму» | подтверждение в Modal | версия `annulled` (причина «сумма изменена»), её ссылка недействительна, её `pending`-попытки → `failed` «ссылка аннулирована»; событие `quote-annulled`, уведомление |
| `awaiting-payment` | `cancelled` | Демо-панель: «Отменить заказ» | выбрана причина | версия `annulled` (причина «заказ отменён»), её `pending`-попытки → `failed`; событие `cancelled`, уведомление |
| `paid` | `processing` | Демо-панель: «Передать в обработку» | — | событие, уведомление |
| `processing` | `shipped` | Демо-панель: «Отметить отправку» | — | событие, уведомление |
| `shipped` | `completed` | Демо-панель: «Завершить заказ» | — | событие, уведомление |

Отдельно:

- «Провайдер отказал» статус **не меняет** (остаётся `awaiting-payment`), попытка → `failed`,
  уведомление «Оплата не прошла».
- `paid → cancelled` в демо **нет**: отмена оплаченного заказа — возврат денег, это процедура
  Admik. Демо-панель в статусе `paid` и дальше показывает: «Оплаченный заказ не редактируется.
  Корректировки — через возврат или доплату в рабочей системе.»
- Покупатель сам заказ не отменяет и не редактирует; на странице заказа подсказка «Чтобы изменить
  или отменить заявку, напишите менеджеру в Telegram {handle}.» (§2.14).

### 3.3 Модель демо-данных

Файл типов `src/types/order.ts` создаёт разработчик ЛК **ровно с этими полями**. Деньги — целые
копейки. Даты — ISO-строки. Email хранится нормализованным: `trim().toLowerCase()`.

```ts
import type { AttrStatus, PriceType } from '@/types/catalog';

export type OrderStatus =
  | 'received' | 'negotiation' | 'awaiting-payment' | 'paid'
  | 'processing' | 'shipped' | 'completed' | 'cancelled';

export type BuyerType = 'person' | 'company';

/**
 * Пункт строки параметров в снимке: текст и статус значения (§4.10). Без статуса снимок выдавал бы
 * «6000–8000 ГГц» или «N/sma-мама» за подтверждённые значения.
 */
export interface OrderSpecPoint {
  text: string;
  status: AttrStatus;          // inferred — «*» и сноска; needs-review — «Уточняется» + note
  note?: string;
}

/** Снимок позиции на момент заявки. Не меняется никогда. */
export interface OrderItemSnapshot {
  lineId: string;              // 'l1', 'l2', … внутри заказа
  productId: string;
  slug: string;
  code: string;                // «Код в каталоге» на момент заявки
  name: string;
  categoryId: string;
  spec: OrderSpecPoint[];      // пункты getSpecLine (§4.7) на момент заявки — specPointsOf(product)
  specSummary?: string;        // УСТАРЕЛО: только у заказов, сохранённых до `spec`; новые не пишут
  priceType: PriceType;
  unitPrice: number | null;    // null — «по запросу»
  quantity: number;
}

/** Строка версии согласования. Цена обязательна. */
export interface QuoteLine {
  lineId: string;              // = lineId снимка или новый 'm1', 'm2', … для добавленной менеджером
  productId: string;
  code: string;
  name: string;
  quantity: number;
  unitPrice: number;
  lineTotal: number;           // unitPrice × quantity
  origin: 'request' | 'added-by-manager';
}

export type QuoteStatus = 'issued' | 'annulled' | 'paid';

export interface QuoteVersion {
  version: number;             // 1, 2, …
  createdAt: string;
  lines: QuoteLine[];
  removedLineIds: string[];    // позиции заявки, исключённые при согласовании
  itemsTotal: number;
  discount: number;            // 0 ≤ discount ≤ itemsTotal
  discountNote: string;        // «Промокод DEMO10» или пусто
  delivery: number;            // ≥ 0
  deliveryNote: string;        // «Доставка до Москвы» или пусто
  total: number;               // itemsTotal − discount + delivery
  managerComment: string;
  status: QuoteStatus;
  annulledAt: string | null;
  annulReason: string | null;
  paidAt: string | null;
}

export interface PaymentAttempt {
  id: string;
  version: number;
  amount: number;              // = QuoteVersion.total на момент создания
  status: 'pending' | 'confirmed' | 'failed';
  createdAt: string;
  resolvedAt: string | null;
  failureReason: string | null; // «Провайдер отказал» | «Ссылка аннулирована»
}

export type OrderEventType =
  | 'created' | 'status' | 'quote-issued' | 'quote-annulled'
  | 'payment-confirmed' | 'payment-failed' | 'cancelled';

export interface OrderEvent {
  id: string;
  at: string;
  type: OrderEventType;
  status: OrderStatus;         // статус после события
  title: string;               // текст для журнала (§6.7)
  notify: { buyerEmail: boolean; managerTelegram: boolean };
}

export interface DemoOrder {
  number: string;              // 'DEMO-0001'
  createdAt: string;
  idempotencyKey: string;
  status: OrderStatus;
  buyer: {
    type: BuyerType;
    name: string;
    email: string;
    phone: string | null;
    companyName: string | null; // только для 'company'
    inn: string | null;         // только для 'company'
    comment: string | null;
  };
  items: OrderItemSnapshot[];
  promo: { code: string; percent: number } | null;
  preliminary: {
    knownItemsTotal: number;    // сумма строк с ценой
```

  навсегда оставалась в Skeleton);
- `safePersistOptions({ name, initial, sanitize })` проверяет форму состояния при слиянии:
  `sanitizeCartData`, `sanitizeFavoritesData`, `sanitizeSession`, `sanitizeLoginChallenge`,
  `sanitizeProfiles` (`src/lib/demo-session.ts`), `sanitizeOrdersData` (`src/lib/demo-orders.ts`).
  Неверное поле — значение по умолчанию, битые элементы списков отбрасываются, остальные
  сохраняются; количество прижимается к 1–999; email нормализуется; повторный номер заказа
  отбрасывается, счётчик `seq` не меньше уже выданных номеров;
- если гидратация всё же упала — хранилище считается прочитанным и пустым
  (`usePersistHydrated` → true), а не висит в Skeleton;
- сбой корневого layout — `global-error.tsx` (§2.22) с кнопкой «Сбросить данные этого браузера и
  перезагрузить» (удаляет только ключи `site.storageKeys`).

### 3.4 Расчёт сумм (`src/lib/demo-pricing.ts`)

| Величина | Правило |
|---|---|
| Сумма строки | `fixed`: `unitPrice × quantity`; `request`: **нет суммы** (в интерфейсе «уточнит менеджер», никогда «0 ₽») |
| Сумма позиций с ценой | Σ сумм строк `fixed` |
| Скидка по промокоду (предварительно) | `Math.round(суммаПозицийСЦеной × percent / 100)`; на строки `request` **не начисляется** |
| Доставка до согласования | **«Рассчитает менеджер»** — не 0, не тариф |
| Предварительный итог | только если **нет** строк `request`: `суммаПозицийСЦеной − скидка`. Иначе полного итога **нет**: «Стоимость уточнит менеджер» и отдельной строкой «Известная часть: {сумма}» |
| Итог после согласования | `QuoteVersion.total` — единственное место, где пишется «Итого к оплате» |

Округления только в одном месте (скидка). Форматирование — §4.9.

### 3.6 Версии согласования и ссылки на оплату

- Версия создаётся **только** действием «Выставить к оплате»; черновиков нет (редактирование живёт
  в форме демо-панели до нажатия).
- Ссылка на оплату версии: `/account/orders/{number}/pay?v={version}`.
- В статусе `awaiting-payment` версия заморожена. Изменить что-либо можно только через «Изменить
  сумму»: версия → `annulled`, статус → `negotiation`, форма демо-панели предзаполняется значениями
  аннулированной версии; новое «Выставить к оплате» создаёт версию N+1 с новой ссылкой.
- Старая ссылка `?v=1` после этого открывает состояние B страницы оплаты (§2.15).
- Оплаченная версия (`paid`) не меняется никогда; заказ после `paid` не редактируется (демо-панель
  не показывает полей редактирования).

### 3.7 Оплата (демо-провайдер)

Обработчик подтверждения в `demo-orders.ts` проверяет по порядку и возвращает код результата; UI
показывает текст из §6.7:

| Проверка | Результат | Что меняется |
|---|---|---|
| заказ уже `paid` или дальше | `already-paid` — «Оплата уже подтверждена ранее. Повторное подтверждение ничего не изменило.» | ничего |
| попытка не `pending` | `not-pending` — «Эта попытка оплаты уже обработана.» | ничего |
| версия попытки ≠ активной или аннулирована | `stale-link` — «Подтверждение отклонено: ссылка на оплату устарела (версия {v} аннулирована).» | попытка → `failed` «Ссылка аннулирована» |
| сумма попытки ≠ итогу версии | `amount-mismatch` — «Подтверждение отклонено: сумма не совпадает с выставленной.» | попытка → `failed` |
| всё совпало | `confirmed` — «Оплата подтверждена. Заказ {№} оплачен.» | попытка `confirmed`, версия `paid` (`paidAt`), заказ `paid`, событие, уведомления |

«Провайдер отказал» → попытка `failed` «Провайдер отказал», статус прежний, уведомление; Notice
danger «Оплата не прошла: провайдер отказал. Можно попробовать снова.», кнопка «Оплатить» снова
доступна (создаст новую попытку).

Нажатие «Оплатить», когда у версии уже есть `pending`, новую попытку не создаёт. Возврат на
`?return=1` и прямой заход на любой адрес **ничего не оплачивают**: статус меняет только
«Провайдер подтвердил оплату».

   промокоду {code}: {percent} % от позиций с ценой из прайса» или «Промокода нет».

4. «Доставка, ₽» (Input `sm`, обязательна, 0 допустим) + «Комментарий к доставке» (Input,

   их на каждый введённый символ.

**Раскладка формы зависит от ширины самой формы — container queries** (`@container`), а не окна:
панель стоит в узкой колонке страницы заказа, и на 1024 px сетка строк по брейкпоинту md сжимала
название до столбика букв. С `@min-[40rem]` — сетка строк `minmax(0,1fr) 7.5rem 7.25rem 7rem 6.5rem`
с общими заголовками; уже — карточки (название, ниже цена, количество, сумма); блоки «Добавить
позицию» и пары полей скидки/доставки — в строку с `@min-[32rem]`.

Денежные поля формы вводятся в рублях (запятая или точка, до 2 знаков после, пробелы разрядов
допустимы) и сохраняются в копейках (`parseRublesInput`). **Пустое поле и «не число» различаются**
(`parseMoneyField`: пусто → `null`, не число → `NaN`): «1 000 руб» или «12,345» — ошибка, а не тихий
0; пустая скидка — 0. Скидка, пока её не правили руками, следует за ценами (процент промокода).
Ошибки формы — §6.5. Отмена:

покупателя», «Нет возможности поставить», «Другое» (тогда Input «Уточните причину», обязательно).

### 3.11 Вход по коду, сессия, корзина и избранное

- Код: §2.12. Сессия — `demoSession`. «Выйти» удаляет сессию; корзина и избранное в браузере
  остаются как есть (копия уже сохранена в профиле).
- **Объединение при входе:** корзина = объединение гостевой и профильной по `productId`; если товар
  есть в обеих — `quantity = max(гостевое, профильное)` (не сумма — повторный вход не удваивает
  количество). Промокод — гостевой, если есть, иначе профильный. Избранное = объединение, порядок:
  гостевые, затем профильные, без повторов. Результат записывается и в гостевое хранилище, и в
  профиль.
- Пока сессия есть, каждое изменение корзины и избранного дублируется в профиль.
- Toast после входа: «Вы вошли как {email}» + если объединение добавило позиции — вторая строка
  «В корзину добавлено позиций из профиля: {n}».
- Заказы видны только той сессии, чей email совпадает с `order.buyer.email`.

## 4. Каталог: подбор, сортировка, вид, форматы

Логика отбора уже реализована движком **`src/lib/catalog/`** (`applyQuery`, `parseCatalogState`,
`serializeCatalogState`, `catalogQueryString`, `removeChip`, `resetFilters`, `suggest`,

группы, подписи, счётчики, чипы, порядок характеристик и форматы берутся из движка. Этот раздел
описывает, как интерфейс показывает результат движка, и фиксирует его контракт для разработчиков
страниц. При расхождении побеждает движок, а раздел обновляется (с записью в журнале).

  **`window.history.replaceState(null, '', basePath + query)`** — без запроса к серверу (Next 16
  синхронизирует нативный History API с `useSearchParams`/`usePathname`; `router.replace` тянул RSC
  страницы целиком на каждый клик), без прокрутки и без записи в историю «Назад». Страницу на 1
  сбрасывают сами помощники движка (`toggleFilterValue`, `setRangeFilter`, `setFrequency`,
  `setPriceRange`, `setRequestOnly`, `setStrict`, `removeChip`, `resetFilters`).
- Переход по страницам — настоящие ссылки `next/link` (`scroll={false}`, router push): «Назад»
  браузера возвращает на прошлую страницу, состояние снова берётся из URL. Прокрутка к `#results` и
  фокус на нём — **только после клика по ссылке пагинации** (PaginationFocus, §5.9.21); смена страницы
  по другой причине (сортировка, подбор, «Назад», исправление `page`) фокус не трогает.
- `page` больше числа страниц — движок возвращает последнюю валидную (`QueryResult.page`); если она
  отличается от запрошенной, адрес исправляется тем же `history.replaceState`.

### 4.2 Группы «Подбор по параметрам»

Панель рендерит **`QueryResult.facets` в данном порядке** — состав, подписи, видимость и счётчики
решает движок (`GROUP_LAYOUT` в `filters.ts`). Справочно, состав по группам категорий:

| Контекст | Группы (подпись движка) |
|---|---|
| Весь каталог, поиск | Категория · Частота · Цена · Цена по запросу |
| Антенны (корень и подкатегории, кроме мини) | Категория (подкатегории) · Конструкция · Модель · Частота · КУ (дБи) · Усиление · Разъём · Масса · Цена · Цена по запросу |
| Мини-антенны | Модель · Частота · КУ · Цена · Цена по запросу |
| Чехлы | Совместимая модель · Цена · Цена по запросу |
| Мачты | Высота · Масса · Допустимая нагрузка · Цена · Цена по запросу |
| МШУ | Частота · Усиление · RF-разъёмы · IP67 · Разъём питания · Цена · Цена по запросу |
| Радиочастотные фильтры | Группа · Частота · Разъёмы · Ослабление · Затухание · Цена · Цена по запросу |
| Кабельные сборки | Длина кабеля · Кабель · Разъём 1-го конца · Форма 1-го конца · Разъём 2-го конца · Форма 2-го конца · Цена · Цена по запросу |
| Аттенюаторы | Диапазон ослабления · Макс. мощность · Цена · Цена по запросу |

Правила движка, которые интерфейс должен показать честно:

- Группа скрыта, если в текущем наборе меньше двух различающих значений (товар без значения — тоже
  «значение»); активная группа видна всегда. Мачты и аттенюаторы (по одной позиции) — без групп:
  если `facets` пуст, панель и кнопка «Параметры» не рендерятся (§2.4).
- `needs-review` не участвует ни в одной группе (Тип8 «N/sma-мама», кабель «RG-316 / RG-142»,
  «6000–8000 ГГц», «0.4» без единицы). Если у группы `excludedCount > 0`, под ней подпись
  `text-caption text-ink-muted`: «У {n} {товара|товаров} значение уточняется — в подборе не
  участвует.» Если в группе есть выбор и `missingCount > 0` — ещё «У {n} {товара|товаров} значение
  не указано — в выдачу не попадают.» (неизвестное ≠ «нет»).
- Счётчик опции — сколько будет результатов, если её выбрать при остальных активных группах. Опция с
  `count = 0` — неактивна (`disabled`), но не скрыта; выбранная — активна всегда.
- Внутри группы — ИЛИ, между группами — И.
- «Конструкция» не показывается там, где видна группа «Категория» (подкатегории антенн): значения
  почти совпадают (решение координатора, §10); активная «Конструкция» видна всегда.
- Виды фасетов → контролы: `options` → OptionList; `flag` → Checkbox (подпись — `label` фасета)
  под **видимой** `legend` = `facet.groupLabel` — подпись характеристики, как у колонки таблицы
  (IP67 → «Защита»): одинокий чекбокс без заголовка не читался как группа; `range` → RangeFilter
  (единица — `unitLabel`, только в `legend`); `frequency` → FrequencyFilter (§4.3); `price` →
  RangeFilter в рублях; `request` → Checkbox «Цена по запросу» (с количеством; `legend` — `sr-only`,
  она повторила бы подпись чекбокса).
- Переключатель **«Только подтверждённые значения»** (`strict`) — последней строкой панели, только
  если `QueryResult.strictAvailable`; подсказка «Без значений, у которых единица не указана в прайсе и
  принята по контексту.» Он действует на все группы и на поиск.

### 4.3 Частотный подбор

Формулы (движок, `frequency.ts`, границы включительно): одна частота f — `f_min ≤ f ≤ f_max`;
диапазон [a, b] «Есть пересечение» (по умолчанию) — `f_min ≤ b` и `f_max ≥ a`; «Покрывает весь
диапазон» — `f_min ≤ a` и `f_max ≥ b`. Участвуют `confirmed` и (без `strict`) `inferred` в МГц;
`needs-review` — никогда. Товары без частоты при активном подборе не показываются. Контрольный
пример (ТЗ §14): `freq=1000` → Тип1 (700–1100) **есть**, Тип2 (360–980) **нет**.

Интерфейс группы «Частота» (сверху вниз):

1. Одно поле Input `sm` (`inputMode="decimal"`), sr-подпись «Частота или диапазон, МГц», плейсхолдер
   «1000 или 900–1100». Разбор — `parseFrequencyInput`: число или диапазон через дефис/тире,
   запятая и точка, единицы «МГц»/«ГГц» («2,4 ГГц» → 2400). Применяется по Enter или blur.
2. Подсказка `text-caption text-ink-muted`: «Число в МГц или диапазон через дефис. Можно «2,4 ГГц».»
3. RadioGroup: «Есть пересечение» (по умолчанию) / «Покрывает весь диапазон» — активна, только когда
   задан диапазон (min ≠ max); для одной частоты режимы совпадают.
4. Подсказка `text-caption text-ink-muted`: «Пересечение — диапазон позиции хотя бы частично
   попадает в заданный. Покрывает весь — позиция работает во всём заданном диапазоне.»
5. Если у фасета `excludedCount > 0` — подпись «У {n} {товара…} частота уточняется (6000–8000 ГГц) —
   в подбор по частоте не попадают.»

Ошибка ввода (разбор вернул null) — под полем: «Введите частоту в МГц, например 1000 или 900–1100».
Пока есть ошибка, значение не применяется.

### 4.4 Цена

RangeFilter «от / до» в целых рублях (единица — в `legend` «Цена, ₽», у полей суффикса нет) →
`price`. Checkbox «Цена по запросу» → `request`
(виден, только если в наборе есть и такие товары, и товары с ценой). Семантика движка — ИЛИ внутри
измерения «цена»:

| Задано | Показываются |
|---|---|
| ничего | все |
| только диапазон | товары с ценой в диапазоне (без «по запросу» — их цена неизвестна) |
| только «Цена по запросу» | только «по запросу» |
| диапазон + «Цена по запросу» | с ценой в диапазоне **или** «по запросу» |

### 4.5 Поведение панели

**Desktop (≥ lg):** чекбоксы, радио, флаги применяются сразу; числовые поля — по Enter или blur. В
форме панели есть `sr-only` кнопка `type="submit"` «Применить параметры» с **`tabIndex={-1}`** —
неявная отправка по Enter работает при нескольких полях, но невидимая кнопка не забирает фокус
(иначе он «пропадал» с экрана, WCAG 2.4.7); отправка формы ничего не перезагружает. Счётчик
результатов в Toolbar — единственный live-регион выдачи (`role="status"`, `aria-live="polite"`,
`aria-atomic="true"`): «Найдено: {N} {товар…}».

**Mobile (< lg):** Drawer (§5.9.18). При открытии текущее состояние выдачи копируется в черновик
(`CatalogState`), фокус — на саму форму панели (`tabIndex={-1}`, `data-autofocus`: первым
фокусируемым было бы поле частоты, и на телефоне сразу выезжала бы клавиатура); правки меняют только
черновик, а `applyQuery` по черновику даёт предварительный
счёт для кнопки «Показать {N} {товар…}» (sr-only live-регион в подвале Drawer: «Будет показано {N}
{товар…}»). «Показать» записывает черновик в URL и закрывает Drawer, фокус — на кнопку «Параметры».
Закрытие крестиком/Esc/подложкой черновик отбрасывает без подтверждения. «Сбросить» —
`resetFilters(черновик)`, Drawer не закрывается. При N = 0 кнопка неактивна с текстом «Нет
подходящих товаров».

**ActiveFilters (чипы):** из `QueryResult.activeChips` (подписи — движка, §6.3); удаление —
`removeChip`. Фокус после удаления — на следующий чип, если его нет — на предыдущий, если чипов не
осталось — на `#results`. После чипов — Button `link` «Сбросить всё» (`resetFilters`: поиск,
сортировка и вид сохраняются; фокус — на `#results`).

### 4.6 Сортировка

Ключи и правила — движок (`state.ts`, `sortProducts` в `query.ts`):

| `sort` | Подпись в каталоге | Подпись в поиске (`q` не пуст) | Правило |
|---|---|---|---|
| `default` | По порядку прайса | **По релевантности** | без `q` — `sortIndex`; с `q` — ранг поиска, при равенстве `sortIndex` |
| `price-asc` | Сначала дешевле | Сначала дешевле | цена по возрастанию; **«по запросу» — всегда в конце**, между собой по `sortIndex` |
| `price-desc` | Сначала дороже | Сначала дороже | цена по убыванию; **«по запросу» — всегда в конце** |
| `name` | По названию | По названию | `Intl.Collator('ru', { numeric: true, sensitivity: 'base' })` (Тип2 раньше Тип10), при равенстве `sortIndex` |

Подписи каталога — `SORT_LABELS` движка; в поиске подпись `default` заменяется на «По релевантности»
(в одном месте — SortSelect). «По запросу» никогда не сортируется как 0.

### 4.7 Вид списка и колонки

Два вида: `list` (по умолчанию) и **«Плитка»** (`grid`). Вид `list` — настоящая таблица там, где
она помещается, ниже — список строк; **подпись переключателя честная**: «Таблица» там, где
показывается таблица, «Список» — там, где строки (§5.9.20).

| Ширина | `list` | `grid` |
|---|---|---|
| без панели (мачты, аттенюаторы, главная, избранное): ≥ lg | ResultsTable — `<table>` | ResultsGrid: 3 колонки на lg, 4 на xl |
| рядом с панелью: ≥ 84rem (1344 px) | ResultsTable | ResultsGrid: 3 колонки с xl |
| рядом с панелью: lg … 84rem | ResultsList (подпись «Список») | ResultsGrid: 2 колонки |
| < lg | ResultsList | ResultsGrid (1 колонка, 2 с sm) |

Почему 84rem: колонке выдачи рядом с панелью на 1024 px достаётся ~649 px, на xl 880–944 px, а
таблица антенн и МШУ в натуральную ширину — 1050+ px. С 84rem (контент 80rem + поля 2 × 2rem)
колонка выдачи — полные 944 px, и с ужатыми ячейками помещаются все категории.

Классы ResultsGrid: рядом с панелью — `grid gap-4 lg:gap-6 grid-cols-1 sm:grid-cols-2 xl:grid-cols-3`;
там, где панель не рендерится (§2.4), — `grid gap-4 lg:gap-6 grid-cols-1 sm:grid-cols-2
lg:grid-cols-3 xl:grid-cols-4`. В избранном плитки нет.

Таблица и список рендерятся оба и переключаются CSS (без дублирующихся `id`): в CatalogView таблица
— в обёртке `hidden lg:block` / `hidden min-[84rem]:block`, список — `lg:hidden` /
`min-[84rem]:hidden`; на главной и в избранном — `<table class="hidden lg:table">` и
`<ul class="lg:hidden">`.

**Таблица в CatalogView** — обёртка `relative -mx-1 overflow-x-auto px-1` (страховка: страница по
горизонтали не прокручивается никогда; `px-1` — чтобы кольцо фокуса у краёв не обрезалось).
Колонка названия — от `11.5rem`; внутренние поля средних ячеек `px-2.5`; заголовки колонок
переносятся (`align-bottom`), значения — нет: у колонок с числами, единицами, типом кабеля и
одиночным разъёмом (`connector`, `power_connector`, `cable_type`, `gain_dbi`, `gain_db`,
`cable_length`, `height`, `weight`, `max_load`, `attenuation_range`, `max_power`, `rejection`,
`insertion_loss`) — `whitespace-nowrap`; составные колонки («Разъёмы», «1-й/2-й конец») —
`min-w-[7.5rem]`, переносятся по пробелу и «—», но не внутри «SMA-female».

**Строка списка (ResultsList)** на < md — столбиком (название → мета → параметры → шкала → цена и
действия); **с md — в одну строку**: слева название, мета, параметры и шкала, справа цена и действия
на базовой линии названия (`md:grid-cols-[minmax(0,1fr)_auto] md:items-baseline`) — строка вдвое
ниже, на экране вдвое больше позиций.

**Колонки таблицы** — «Наименование» · колонки категории · «Цена» · действия (`th` sr-only
«Действия»). Заголовок колонки из одной характеристики — подпись движка `attributeLabel(code,
root)`; составные колонки названы здесь. Колонки категории страницы:

| Страница | Колонки (коды) |
|---|---|
| `antennas` (корень) | Конструкция (`antenna_design`) · Частотный диапазон (`frequency`) · КУ (`gain_dbi`) · Разъём (`connector`) |
| `antennas/log-periodic`, `corner`, `yagi`, `horn`, `micro-horn` | Частотный диапазон · КУ · Разъём |
| `antennas/mini` | Частотный диапазон · КУ |
| `covers` | Совместимая модель (`compatible_model`) |
| `masts` | Высота · Масса · Допустимая нагрузка |
| `lna` | Частотный диапазон · Усиление (`gain_db`) · **Разъёмы** (порт 1 — порт 2) · Защита (`ip67`) · Разъём питания |
| `rf-filters` (корень) | Группа (`filter_group`) · Частотный диапазон · **Разъёмы** |
| `rf-filters/bandpass`, `channel` | Частотный диапазон · **Разъёмы** |
| `rf-filters/cavity` | Частотный диапазон · Ослабление (`rejection`) |
| `cables` | Длина кабеля · Кабель · **1-й конец** (разъём + форма) · **2-й конец** |
| `attenuators` | Диапазон ослабления · Макс. мощность |
| смешанный (`/catalog`, `/search`, `/favorites`, главная) | Категория (листовая) · **Характеристики** |

- Значение ячейки — `formatAttrValue` движка через **TechText** (§4.9); составные: «Разъёмы» —
  `{порт 1} — {порт 2}`, «1-й/2-й конец» — `{разъём} {форма}` (без формы — только разъём); статус
  составной ячейки — худший из частей. Название товара и листовая категория — тоже через TechText.
- Ячейки строки выровнены по **базовой линии первой строки** (`align-baseline`): название и цена
  (16 px), значения (14 px) и подпись кнопки 32 px стоят на одной линии.
- Код позиции (в таблице и списке) — ProductCode: `font-mono` + `<span class="sr-only">Код в
  каталоге: </span>` (+ `title`): без подписи «ANT-001» читается как заводской номер. Badge
  «Уточняется» у названия — только если спорное значение не видно в колонках строки.
- **Характеристики** (смешанный вариант) и **specSummary** (строка под названием в ResultsList, в
  подсказках нет, в снимке заказа — пунктами со статусами `spec`, §3.3) — пункты `getSpecLine(product)`
  (в разметке — SpecLine, текстом — `formatSpecLine`): 2–3 ключевых
  параметра по корневой категории через « · » («700–1100 МГц · 12 дБи · N-female»). Ключевые
  характеристики ProductCard — те же `getSpecLine` пункты парами «label — text».
- Пункт со статусом `inferred` получает «*», `needs-review` — Badge «Уточняется» (§4.10).
- Частота в ячейке — значение и под ним BandScale `sm` (§5.10). В смешанном варианте BandScale — под
  строкой характеристик.
- Нет значения — «—» с `<span class="sr-only">не указано</span>`.

### 4.9 Форматирование значений

Форматы данных каталога — **функции движка**; свои форматтеры для них не пишутся. Всё, чего в
движке нет (даты, склонение, заглавная буква, адрес ячейки), — в `src/lib/format.ts`.

| Что | Функция / правило | Пример |
|---|---|---|
| Цена | `formatPrice(kopecks)` (`price.ts`): группы разрядов и пробел перед «₽» — U+00A0, копейки только если не 0. Без `Intl` — сервер и браузер дают одну строку (нет расхождений гидратации) | 13 000 ₽; 13 000,50 ₽ |
| Цена товара | `formatProductPrice(product)` → «13 000 ₽» или `PRICE_ON_REQUEST_LABEL` «Цена по запросу» | — |
| «По запросу» компактно | «По запросу» — таблицы, строки корзины и заказа (своя константа рядом с движком) | По запросу |
| Скидка | `formatPrice(-discount)` — знак «−» (U+2212) ставит движок | −5 400 ₽ |
| Рубли в фильтре | `formatRubles`, `formatRubleAmount` | 20 000 ₽ |
| Значение характеристики | `formatAttrValue(code, value)` (`attributes.ts`): десятичная запятая, без разделителя тысяч, диапазон через «–» без пробелов, U+00A0 перед единицей, г → кг от 1000, см → м от 100, «до» у нагрузки и мощности, флаг IP67 → «IP67», список через « / » | 700–1100 МГц; 18,5 дБи; 16 кг; 1 м; до 5 Вт |
| Частота | всегда в МГц, как в прайсе; `needs-review` — в исходной единице | 4900–6100 МГц; 6000–8000 ГГц |
| Запрос частоты | `formatFrequencyQuery` | 900–1100 МГц |
| Строка параметров | `formatSpecLine(getSpecLine(product))`; в разметке — SpecLine: пункты через `NBSP + «· »` (строка не начинается с «·») | 700–1100 МГц · 12 дБи · N-female |
| Текст в ячейке и опции | первая буква заглавная (`capitalize` в `format.ts`); в строке параметров — как в данных | Логопериодическая |

### 4.11 Поиск

- Движок — `searchProducts` (`src/lib/catalog/search.ts`) поверх `Product.searchText` и
  `src/lib/search-normalize.ts`: регистр, ё/е, кириллические «М»/латинские «M», «Тип 1»/«Тип1»,
  МГц/MHz, «мама»/female, запятая/точка, тире. Все слова запроса должны найтись (И). **Число в
  запросе — ещё и частота**: «2400», «2,4 ГГц», «900-1100» находят позиции, чей подтверждённый
  диапазон их покрывает; спорные «6000–8000 ГГц» по частоте не находятся; число перед дБ/дБи/г/кг/м/
  см/Вт — не частота. **Единица сопоставляется целым словом**, а не началом слова: «10 дБ» не
  находит «10–12 дБи» (дБ и дБи — разные величины), «1 м» — «мини»; однозначные единицы (дБ, дБи,
  МГц, ГГц, кГц) — целым словом и без числа; одиночные «м», «г» без числа — по-прежнему начало
  слова. Релевантность: точная модель > все слова в названии > прочее. Похожие названия товары не
  объединяют.
- **Запрос без единого токена** (только знаки препинания, невидимые символы) — пустой запрос:
  `parseCatalogState` такой `q` не сохраняет (§2.7 «пустой запрос»).
- Информационные страницы — `site.searchablePages` (сопоставление после `normalizeSearchText`).
- Подсказки в шапке — `suggest(q, 9, { products, categories })`: сначала до 3 категорий, затем
  товары; SearchCombobox (§5.9.36), с `site.catalog.suggestMinChars` символов, задержка
  `suggestDebounceMs`. Индекс подсказок (`getSearchIndex()`) **не встраивается в разметку
  страниц**: его отдаёт статический `/api/search-index`, поле загружает его при первом фокусе или
  вводе, один раз на вкладку.

### 5.3 Типографика

**Шрифты — IBM Plex Sans + IBM Plex Mono** (Google Fonts через `next/font/google`).

Почему: (1) полноценная, тщательно спроектированная кириллица, а не «дорисованная» латиница; (2) у
Plex Sans **табличные цифры по умолчанию** (проверено по файлу Google Fonts: ширина всех цифр
600/1000 em) — колонки частот, цен и количеств выравниваются без настроек; (3) инженерное
происхождение гарнитуры (IBM) соответствует техническому каталогу, а моноширинный Plex Mono из той же
семьи даёт однородный голос кодам (`ANT-001`), адресам ячеек и исходному тексту прайса; (4) Plex Sans
на Google Fonts — вариативный (ось `wght` 100–700), один файл на подмножество.
Отклонено: Inter (шаблонный выбор), Golos Text (хорош для кириллицы, но цифры пропорциональные по
умолчанию, а моноширинной пары нет).

Подключение — **`src/app/fonts.ts`** (создаёт разработчик каркаса ровно так):

```ts
import { IBM_Plex_Mono, IBM_Plex_Sans } from 'next/font/google';

export const plexSans = IBM_Plex_Sans({
  subsets: ['latin', 'cyrillic'],
  display: 'swap',
  variable: '--font-plex-sans',
}); // вариативный: weight не указывается

export const plexMono = IBM_Plex_Mono({
  subsets: ['latin', 'cyrillic'],
  weight: ['400', '500'],
  display: 'swap',
  variable: '--font-plex-mono',
  preload: false, // моно — вторичный шрифт: коды и исходный текст прайса
});
```

В `layout.tsx`: `<html lang="ru" className={`${plexSans.variable} ${plexMono.variable}`}>`. В
`globals.css` уже есть `@theme inline { --font-sans: var(--font-plex-sans), …; --font-mono:
var(--font-plex-mono), … }`.

### 5.6 Радиусы, границы, тени, z-index, движение

| Токен | Значение | Где |
|---|---|---|
| `rounded-xs` | 2 px | чекбокс, сегмент внутри Segmented |
| `rounded-sm` | 4 px | кнопки, поля, Badge, чипы, Select |
| `rounded-md` | 6 px | карточки, плитки, панели, Notice, Toast, NoPhoto |
| `rounded-lg` | 8 px | Modal, Drawer (видимые углы) |
| `rounded-full` | — | счётчики, точки статусов, маркеры таймлайна, BandScale |

Границы: 1 px везде; 1,5 px у чекбокса/радио; 2 px — только кольцо фокуса, рамка маркера текущего
шага и полоса текущего пункта навигации. `border` без цвета даёт `line` (база).

Тени — только у всплывающих слоёв: `shadow-popover` (подсказки поиска, выпадающие списки),
`shadow-overlay` (Modal, Drawer, Toast). У карточек и панелей теней нет; наведение на карточку —
`border-line-strong`.

z-index: `z-sticky` 20 (липкая панель каталога, сводка), `z-header` 30, `z-popover` 40 (подсказки),
`z-overlay` 50, `z-toast` 60, `z-skip` 70 (ссылка «Перейти к содержимому»). Modal/Drawer — нативный
`<dialog>.showModal()` в top layer, вне шкалы. Toast не показывается поверх открытого Modal.

Движение: `duration-fast` 120 ms (цвет, рамка), `duration-base` 200 ms (появление), `duration-slow`
240 ms (выезд Drawer); `ease-standard` для появления, `ease-exit` для ухода. Анимации:
`animate-slide-in-right` / `-left` (Drawer), `animate-rise-in` (Modal, Toast), `animate-fade-in`,
`animate-spin` (индикатор загрузки). Закрытие — без анимации. Анимируются только `opacity` и
`transform`. При `prefers-reduced-motion: reduce` все длительности → 0,01 ms (база в `globals.css`).
Плавная прокрутка не используется.

### 5.7 Фокус и состояния взаимодействия

- `:focus-visible` — `outline: 2px solid var(--color-focus); outline-offset: 2px` (база). Не
  отключается и не переопределяется цветом бренда. В контейнерах с `overflow` (строки подсказок,
  ячейки) — утилита `focus-inset` (кольцо внутрь). На `data-surface="inverse"` кольцо белое.
- Фокус не держится на одном цвете: это контур формы элемента + отступ.
- Состояния (у всех интерактивных): **покой · наведение · нажатие · фокус · неактивно** (+ загрузка
  у кнопок, выбрано у переключателей, ошибка у полей). Наведение никогда не единственный способ
  что-то увидеть (подсказки, меню — тоже по клику/клавиатуре).
- Курсор: `cursor-pointer` у кнопок, ссылок, строк-опций; `not-allowed` у неактивных.
- Минимальная цель нажатия — 24×24 (WCAG 2.5.8); на < lg — 44×44 для иконок, кнопок количества и
  строк опций. Как это достигается без отдельной вёрстки: QuantitySelector `md` на < lg — 48
  (§5.9.26); IconButton `header` — 44 (шапка); у кнопок `sm` в карточке на < lg —
  `max-lg:min-h-11 max-lg:min-w-11` (min-* не спорит с размером кнопки); строки опций в Drawer —
  `min-h-11`, поля в Drawer — Input `lg` (44).
- **Кольцо фокуса не обрезается** контейнером с прокруткой: у прокручиваемой колонки
  (FilterPanel, полоса CategoryNav, обёртка таблицы) — внутренний отступ ≥ 4 px (outline 2 px +
  отступ 2 px), скомпенсированный отрицательным полем, и `scroll-padding`; где отступа нет —
  `focus-inset`.

#### 5.9.7 Field

Обёртка `flex flex-col gap-1.5`. Порядок: **Label → Hint → Error → контрол** (+ счётчик символов
под контролом справа).

- Label — `text-small font-medium text-ink`; необязательное поле: ` (необязательно)` —
  `font-normal text-ink-muted`. Обязательность не отмечается звёздочкой: в начале формы фраза «Все
  поля обязательны, кроме отмеченных «необязательно».»
- Hint — `text-small text-ink-muted`, `id="{id}-hint"`.
- Error — `text-small text-danger flex gap-1.5 items-start`, иконка `circle-alert` 16 (`mt-0.5`), текст

  перепроверка на blur и при вводе (исчезает, как только поле стало верным).
- Контрол: `aria-describedby="{id}-hint {id}-error"` (только существующие), `aria-invalid="true"` при

#### 5.9.21 Pagination

`<nav aria-label="Страницы" class="mt-8 flex items-center justify-between gap-2">`. Элементы —
ссылки `next/link` (`scroll={false}`, с `page` в URL; работают без JS), высота `h-10`, `min-w-10`,
`rounded-sm text-small font-medium`: «Назад» (`chevron-left`, `rel="prev"`) и «Вперёд»
(`chevron-right`, `rel="next"`) — вариант secondary `md`; номера — ghost (sr-префикс «Страница »);
текущая — `bg-ink text-ink-inverse` + `aria-current="page"`; на крайних страницах «Назад»/«Вперёд»
неактивны (`aria-disabled`, без `href`). Номера: первая, последняя, текущая ± 1, пропуски «…»
(`aria-hidden`). На < sm вместо номеров — текст «Страница {n} из {m}». Не рендерится при одной
странице. **Фокус и прокрутка к `#results` — только после клика по ссылке этой навигации**
(PaginationFocus: клик ловится делегированием на `nav`, клики с модификаторами не считаются); смена
страницы по другой причине — сортировка, подбор, «Назад» браузера, исправление `page` — фокус не
трогает.

#### 5.9.26 QuantitySelector

`inline-flex items-stretch rounded-sm border border-line-strong bg-surface`: кнопка «−» | поле |
кнопка «+». Высота — **полная, вместе с рамкой**, по шкале Button/IconButton: **`sm` 32, `md` 40 (на

border-x border-line focus-inset`, `type="text" inputMode="numeric"`, sr-подпись «Количество:
{name}». Пределы 1–999: пустое/0/не число на blur → прежнее значение; > 999 →
999 и подсказка «Не больше 999 шт. — для крупных партий напишите менеджеру». В корзине изменение
применяется сразу (ввод с клавиатуры — с задержкой 300 мс).

#### 5.9.31 Toast

ToastRegion (один на приложение, в корневом layout) — три элемента:

1. **Два постоянных скрытых live-региона** (`sr-only`), которые есть в разметке **с серверной
   отрисовки** — меняется только их текст: `role="status" aria-live="polite" aria-atomic="true"` для
   обычных сообщений и `role="alert" aria-live="assertive" aria-atomic="true"` для ошибок (`tone:
   'error'`). Сообщение, вставленное в DOM сразу с ролью и текстом, скринридеры часто пропускают.
   Текст объявления — «{message}. {detail}» одной фразой; узел — с ключом id сообщения, поэтому два
   одинаковых сообщения подряд объявляются оба. Закрытое или вытесненное сообщение убирает своё
   объявление (предыдущее не повторяется).
2. **Видимый регион** `role="region" aria-label="Сообщения"`, `data-print="hidden"`, `fixed z-toast
   bottom-4 inset-x-4 sm:left-auto sm:right-4 sm:w-[24rem] flex flex-col gap-2
   pointer-events-none` — в нём кнопки сообщений («Вернуть», «Перейти в корзину», «Закрыть
   сообщение»). **У видимых сообщений роли нет** (иначе объявление дублировалось бы); фокус не
   переносится.

Сообщение: `data-surface="inverse" bg-surface-inverse text-ink-inverse rounded-md shadow-overlay px-4
py-3 flex items-start gap-3 text-small animate-rise-in pointer-events-auto`; вторая строка `detail`;
действие — Button `link` тоном `inverse` (белым); закрыть — IconButton `sm` `inverse` `x` «Закрыть
сообщение». Время: 5 с, с действием — 8 с; пауза при наведении и фокусе; не больше 3 одновременно
(старое уходит). Поверх открытого Modal не видны (`<dialog>` в top layer). Тексты — §6.1.

### 5.10 BandScale — спектральная шкала

Единственный «характерный» элемент интерфейса: показывает, где на спектре работает позиция, и даёт
глазу сравнить десятки полосовых фильтров в таблице. Перекликается с концентрическими «волнами» знака
и его оранжевым.

- **Ось:** логарифмическая, `site.catalog.bandScale`: 50 МГц … 10 000 МГц.
  `p(f) = (log10(f) − log10(50)) / (log10(10000) − log10(50))`, ограничить [0, 1].
  `--band-start = p(min) × 100 %`, `--band-width = (p(max) − p(min)) × 100 %`; одиночная частота —
  ширина 0 (CSS даёт минимум 3 px). Функция — `src/lib/band-scale.ts`.
- **Когда рисуется:** у `frequency` со статусом `confirmed` или `inferred` (единица — МГц). У
  `needs-review` («6000–8000 ГГц») шкалы нет.
- **Разметка:** `<div class="band-scale" data-size="sm|lg" data-tone="brand|neutral"><div
  class="band-scale__fill" data-status="confirmed|inferred" style="--band-start:…; --band-width:…">
  </div></div>` в обёртке `aria-hidden` — стили в `globals.css`.
- **Тон (`tone`)** — по умолчанию по размеру. Оранжевый — умеренный акцент, поэтому:
  - `lg` → **`brand`**: заливка `band-fill` (= `brand`), одна шкала на экране (страница товара);
    `inferred` — штриховка вместо сплошной заливки;
  - `sm` → **`neutral`**: в таблицах, списках и плитке десятки шкал на экране — заливка
    `line-strong` на треке `line-subtle` (компонент переопределяет `--color-band-fill`); `inferred`
    — **пунктир** `ink-muted` (штрих 3 px, просвет 2 px): на высоте 4 px мелкая диагональ читалась
    как артефакт. В режиме высокой контрастности — сплошная заливка `CanvasText`.
- **Размеры:** `sm` — высота 4 px, ширина `w-full max-w-40` (таблица, колонка «Характеристики»), `max-w-60` (список, карточка);
  `lg` — 6 px на всю ширину колонки до `max-w-[28rem]` + подписи делений под шкалой.
- **Деления (`lg`):** из `bandScale.ticks` — «100 МГц», «1 ГГц», «10 ГГц» на `p(100)`, `p(1000)`,
  `p(10000)`: риска `w-px h-1 bg-line-strong`, подпись `text-caption text-ink-muted` (крайняя правая
  выравнивается по правому краю).
- **Доступность:** только дублирует текстовое значение, поэтому `aria-hidden`; в режиме высокой
  контрастности — рамка и заливка `CanvasText` (в `globals.css`).

## 7. Доступность

Цель — WCAG 2.2 AA на всех страницах.

- **Клавиатура.** Всё доступно с клавиатуры в логическом порядке; нет ловушек, кроме модальных
  `<dialog>` (Esc закрывает). SkipLink первым. Подсказки поиска — паттерн combobox (§5.9.36).
  Segmented и RadioGroup — стрелками. Ничего не открывается только по наведению.
- **Фокус** (§5.7): видимый всегда, 2 px контур + отступ 2 px, контраст 17,8:1, не только цвет.
  Управление фокусом: после клика по ссылке пагинации → `#results` (другая смена страницы фокус не
  трогает); после удаления чипа → соседний чип (последнего — `#results`); после
  неудачной отправки → ErrorSummary; при открытии Modal → первый элемент тела (в подтверждениях —
  «Отмена»; в Drawer подбора — сама форма); при закрытии Modal/Drawer → кнопка-триггер; после
  «Показать N» → «Параметры». Фокус не прячется под липкой панелью (`scroll-padding-top`) и не
  уходит на невидимые элементы (sr-only кнопка «Применить параметры» — `tabIndex={-1}`); кольцо
  фокуса не обрезается контейнерами с прокруткой (§5.7).
- **Структура.** Один `h1` на страницу, заголовки без пропуска уровней; ориентиры `header`, `nav`,
  `main#content`, `footer`; **у каждого `nav` и `form role="search"` — уникальное доступное имя**
  (§6.9: «Категории каталога», «Информация для покупателей», колонки подвала по заголовкам, «Быстрый
  поиск» / «Поиск по каталогу»); текст вне ориентиров не остаётся (DemoBanner — `section` с именем);
  таблицы данных — `<table>` с `caption`/`th scope`.
- **Подписи полей** видимые; обязательность — словами; подсказки и ошибки связаны
  `aria-describedby`; `aria-invalid`; автозаполнение (`name`, `email`, `tel`, `organization`,
  `one-time-code`); поля ≥ 16 px.
- **Live-регионы** — минимум и с контекстом, и **есть в разметке с первой отрисовки** (меняется
  только текст — вставленный сразу с ролью узел скринридеры часто пропускают): счётчик результатов
  (`role="status"`, `aria-atomic`, «Найдено: 12 товаров»), предварительный счёт в Drawer, статус
  подсказок поиска, Toast (два постоянных скрытых региона polite/assertive, §5.9.31), строка «В
  корзине: N шт.», итоги демо-панели. Счётчики в шапке **не** live (обновляются вместе с Toast).
  Обратный отсчёт повторной отправки кода — не live.
- **Панель подбора:** `form` с доступным именем; группы — `fieldset/legend`; счётчики опций входят
  в подпись («N-female, 4»); неактивные опции — `disabled`; «Показать все» — `aria-expanded`.
- **Не только цвет:** статусы — текстом; выбранное — заливкой `ink` + `aria-pressed`/`checked`;
  ошибки — текстом и иконкой; текущий пункт — полосой и `aria-current`; отличия листов — «≠» и
  начертанием; inferred — «*» и штриховкой (`lg`) / пунктиром (`sm`) шкалы.
- **Контраст** — §5.2. Оранжевый не используется для текста.
- **Цели нажатия** — ≥ 24 px везде, ≥ 44 px для иконок, кнопок количества и строк опций на < lg
  (§5.7).
- **Движение** — только `opacity`/`transform`, ≤ 240 ms; `prefers-reduced-motion` — без анимаций.
- **Масштаб** — вёрстка выдерживает 200 % масштаба текста и ширину 320 px без горизонтальной
  прокрутки страницы; чипы, бейджи, кнопки переносятся, а не обрезаются.
- **Режим высокой контрастности** (`forced-colors`): у кнопок есть рамка 1 px, BandScale рисуется
  системными цветами.
- **Язык** — `lang="ru"`; аббревиатуры единиц не раскрываются (общепринятые).
- **Проверка перед сдачей:** клавиатурный проход сценариев S1–S6 в Playwright; ширины 375 / 768 /
  1024 / 1440; автоматическая проверка axe — если пакет будет добавлен в зависимости (сейчас его
  нет), до этого — ручная проверка по этому списку.

## 8. SEO и метаданные

- **Глобально:** пока `site.seo.allowIndexing = false` (макет на Vercel), `src/app/robots.ts` отдаёт
  `Disallow: /`, а корневой `metadata.robots = { index: false, follow: false }`. Правила ниже
  действуют после переключения флага.
- **Индексируются:** главная, `/catalog`, категории и подкатегории **без query-параметров**, товары,
  `/contacts`, `/delivery`; юридические — когда `site.legal.ready = true`.
- **Не индексируются** (`noindex`) и не попадают в sitemap: `isNoindexPath()` из `site.ts` (поиск,
  корзина, заявка, избранное, вход, ЛК, служебные, юридические до готовности); любые страницы
  каталога с параметрами (`noindex, follow` + `canonical` на путь без параметров); 404.
- **Title:** шаблон `'%s — ' + siteTitle()`; главная — `title.absolute` (§2.2). Тексты title и
  description — в описаниях страниц §2.
- **Адрес сайта** — `SITE_URL` из `@/lib/seo` (модуль `server-only`): `metadataBase`, canonical,
  `og:url`, `og:image`, sitemap, robots, JSON-LD (`absoluteUrl(path)`). Правило — чистая функция
  `resolveSiteUrl(env)` в `src/config/site-url.ts`, первый непустой источник:
  1. `NEXT_PUBLIC_SITE_URL` — боевой домен, задаётся вручную (можно без схемы: `example.ru` →
     `https://example.ru`);
  2. `VERCEL_PROJECT_PRODUCTION_URL` — production-домен проекта Vercel (есть и в превью-деплоях,
     поэтому canonical и картинка превью ссылок ведут на production);
  3. `VERCEL_URL` — адрес конкретного деплоя;
  4. `http://localhost:3000` — локальный запуск без переменных.
  Значение нормализуется (без «/» в конце; неверный адрес — ошибка сборки). Только на сервере:
  системные переменные Vercel в браузер не попадают, в клиентском компоненте адрес получился бы
  другим. **Поля `site.url` в конфиге нет.** Переменные описаны в `.env.example` (§9).
- Open Graph: `og:locale` `ru_RU`, `og:type` `website`, `og:title`/`og:description` =
  title/description, `og:url` = путь страницы; `og:image` — `/brand/logo-mark-512.png` (файл трека
  логотипа). Страницы задают metadata только через `pageMetadata()` / `robotsFor()` — Next сливает
  `robots`/`openGraph` поверхностно, ручная запись сняла бы глобальный noindex.
- **sitemap.ts:** главная, `/catalog`, все категории/подкатегории, все видимые товары,
  `/contacts`, `/delivery` (+ юридические при готовности). Без `lastmod` (дат в данных нет). Карта
  собирается и сейчас, но `robots.txt` ссылается на неё только после снятия запрета; тогда
  `Disallow` — `site.seo.noindexPrefixes` (+ `/legal`, пока тексты не готовы).
- **Структурированные данные:** BreadcrumbList (каталог, категории, товар, контакты, доставка);
  Product без `brand`, `mpn`, `image`, `review`, `aggregateRating`, `availability`; `offers` только для
  `fixed` и только при `currency.assumed = false` (иначе цена в RUB утверждалась бы как факт);
  «по запросу» — без `offers`, никогда `price: 0`. WebSite + SearchAction на главной.
- **Description товара** — §2.6 «SEO»: статус значений передаётся словами (`inferred` — «(единица
  уточняется)»), `needs-review` в описание не попадает.
- **URL:** читаемые латинские slug из данных (`/product/antenna-tip1`), категории
  `/catalog/{parent}/{child}`; товар вне `generateStaticParams` — 404 без рендера
  (`dynamicParams = false`).
- **Заголовки ответа** (`next.config.ts`, одинаково на `next start` и Vercel): `poweredByHeader:
  false` (без `X-Powered-By`); `X-Content-Type-Options: nosniff`; `X-Frame-Options: SAMEORIGIN` и
  `Content-Security-Policy: frame-ancestors 'self'` (то же для браузеров, смотрящих на CSP);
  `Referrer-Policy: strict-origin-when-cross-origin`; `Permissions-Policy: camera=(), microphone=(),
  geolocation=()`. Полная CSP (script-src) в объём макета не входит: inline-скрипты Next требуют
  nonce и динамического рендера каждой страницы.

## 10. Допущения, зависимости, открытые вопросы

**Допущения (мои решения, пересматриваемые):**

1. Телефон в заявке необязателен (§2.10).
